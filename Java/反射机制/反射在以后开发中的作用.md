# 反射机制的反编译的案例：

#### 创建一个工具，提供一个静态变量，静态方法中传入任何一个类的全类名，都可以获取类的所有信息（属性，构造，实例方法）

```java
package reflect;

import java.io.FileNotFoundException;
import java.io.FileReader;
import java.io.IOException;
import java.util.HashMap;
import java.util.Properties;

public class BeanFactory {
    //创造一个哈希数组，通过提供key获取value的方式进行读取信息（static目的是只加载一次且在哪都可以访问到）
    private  static HashMap<String,Object> hashMap = null;

    //写静态代码块是为了在类加载的时候就加载且只加载一次
    static {
        //创建集合的实例
        hashMap = new HashMap<>();

        //创建properties集合对象
        Properties properties = new Properties();
        FileReader fileReader = null;

        //创建流对象
        try {
            fileReader  = new FileReader("bean.properties");

            //集合配合io流来读取配置文件中的信息
            properties.load(fileReader);

            //根据key取出对应的value的值
            String value = properties.getProperty("classNames");

            //通过；来对全类名的字符串进行切割
            String[] classArray = value.split(";");

            //遍历数组
            for (String className : classArray) {
                //获取字节码对象
                Class<?> aClass = Class.forName(className);

                //创建实例(通过转换来的字节码文件转换成对应的实例，类似于就是User这个类本身，只是换了一种创建实例的形式，
                // 且这种形式耦合性更低，起到解耦的作用)
                Object instance = aClass.newInstance();

                //获取对应实例的唯一标识 （将类名首字母改为小写）
                String key = className.replace("com.eagles.pojo.", "");//将前面的包名改为空格
                char[] chars = key.toCharArray();//转化成数组
                Character c = chars[0];//获得首字母c
                String s = c.toString().toLowerCase();//将首字母转换成小写
                key = s +key.substring(1);//拼接

                //将实例添加到集合中
                hashMap.put(key,instance);

            }

        } catch (Exception e) {
            throw new RuntimeException(e);
        }finally {
            //回收资源
            if (fileReader != null){
                try {
                    fileReader.close();
                } catch (IOException e) {
                    throw new RuntimeException(e);
                }
            }
        }
    }

    /*
    提供静态方法 getBean(String id) 用于获取 Bean 实例。
     */
    public  static Object getBean(String id) {
        return  hashMap.get(id);
    }
}
```

# 如何联系这些代码块：

首先，确保你的项目根目录下有一个名为 `bean.properties` 的配置文件。这个文件用于指定哪些类需要由 `BeanFactory` 管理。例如：

```java
# bean.properties
classNames=com.eagles.pojo.User;com.eagles.pojo.Animal
```

这里的 `classNames` 属性值是你想要通过 `BeanFactory` 来管理的类的全限定名（即包含包名的类名），多个类之间用分号 `;` 分隔。

### 2. 定义业务类

假设你有两个简单的 POJO 类：`User` 和 `Animal`。这些类应该至少有一个无参构造函数，因为 `BeanFactory` 使用 `Class.forName(className).newInstance()` 来创建实例。

#### 示例 - User.java

```java
package com.eagles.pojo;

public class User {
    public void sayHello() {
        System.out.println("Hello from User!");
    }
}
```

#### 示例 - Animal.java

```java
package com.eagles.pojo;

public class Animal {
    public void makeSound() {
        System.out.println("Animal sound");
    }
}
```

### 3. 使用 BeanFactory 获取 Bean 实例

现在，你可以编写一个测试类来使用 `BeanFactory` 来获取这些类的实例，并调用它们的方法。

#### 示例 - Test.java

```java
package com.eagles.pojo;

import reflect.BeanFactory;

public class Test {
    public static void main(String[] args) {
        // 获取 User 实例
        Object userInstance = BeanFactory.getBean("user");
        if (userInstance instanceof User) {
            User user = (User) userInstance;
            user.sayHello(); // 输出: Hello from User!
        }

        // 获取 Animal 实例
        Object animalInstance = BeanFactory.getBean("animal");
        if (animalInstance instanceof Animal) {
            Animal animal = (Animal) animalInstance;
            animal.makeSound(); // 输出: Animal sound
        }

        // 测试单例模式
        Animal animal1 = (Animal) BeanFactory.getBean("animal");
        Animal animal2 = (Animal) BeanFactory.getBean("animal");

        System.out.println(animal1 == animal2); // 应该输出 true 如果是单例模式
    }
}
```

### 注意事项

- **静态初始化块**：`BeanFactory` 中的静态初始化块会在类第一次被加载时执行，因此请确保 `bean.properties` 文件路径正确且可访问。
- **异常处理**：在实际应用中，你可能需要更优雅地处理可能出现的异常情况，比如文件找不到或类不存在等。
- **类名转换为键值**：根据你的 `BeanFactory` 实现，类名会被转换成小写首字母的形式作为键值存储在 `HashMap` 中。例如，`com.eagles.pojo.User` 会被转换为 `"user"`。确保你在调用 `getBean` 方法时使用的键值与此规则匹配。

你这段代码实现了一个**简单的 Bean 工厂（IoC 容器）**，通过读取配置文件 `beans.properties`，加载类、创建实例，并将它们放入一个 HashMap 中，供外部通过 id 获取。整体逻辑是清晰的，但在一些细节上可以优化或改进，尤其是在**类名首字母小写生成 key 的方式**上。

## 核心功能简述
你的 `BeanFactory` 类主要完成了以下几件事：

1. 从 `beans.properties` 文件中读取配置；
2. 根据配置中的类名字符串（用分号隔开），动态加载类；
3. 创建这些类的实例；
4. 将实例存入 HashMap，key 是类名首字母小写后的字符串；
5. 提供静态方法 `getBean(String id)` 用于获取 Bean 实例。

## 关于“类名首字母小写”作为 key 的问题
这部分是你重点关心的问题之一：

```java
String key = className.replace("com.eagles.pojo.","");

char[] chars = key.toCharArray();

Character c = chars[0];

String s = c.toString().toLowerCase();

key = s + key.substring(1);
```

### 这段代码的作用：

- 去掉包名前缀 `com.eagles.pojo.`；
- 把剩下的类名首字母小写，作为 key 存入 Map；
- 比如类名为 `UserService` → key 为 `userService`。

### 这种做法在 Spring 等框架中是常见的：

- 在 Spring 中，默认情况下，使用组件扫描时，Bean 的名称就是类名首字母小写的形式。
- 所以你的做法是对 Spring 默认命名策略的一种模拟。

### 不足之处：

- 使用 `char[]` 和 `substring()` 处理字符串显得有些繁琐；
- 如果类名只有一个字符，比如 `A.class`，可能会出错；
- 没有考虑空值、异常等情况。

## 推荐改法：使用更简洁安全的方式

你可以简化成如下一行代码：

```java
String simpleClassName = className.substring(className.lastIndexOf('.') + 1);
String beanName = Character.toLowerCase(simpleClassName.charAt(0)) + simpleClassName.substring(1);
```

### 示例：

|  |  |  |
| --- | --- | --- |
| **全限定类名** | **simpleClassName** | **beanName** |
| com.eagles.pojo.UserService | UserService | userService |
| com.eagles.pojo.UserDAO | UserDAO | userDAO |
| com.eagles.pojo.A | A | a |

这个写法更加简洁、健壮、可读性更高。

## 其他建议和优化点

---

### 1. **避免使用** `Class.newInstance()`**（已过时）**

Java 9 开始，`Class.newInstance()` 被标记为废弃，推荐使用 `Constructor.newInstance()`，可以更好地处理异常。

不过如果你只是调用无参构造函数，目前这种方式还是可用的。

---

### 2. **使用日志代替** `e.printStackTrace()`

抛出 `RuntimeException` 并封装原始异常是可以接受的，但最好加上日志记录。

---

### 3. **使用** `Map<String, Object>` **替代** `HashMap`

为了接口编程，声明类型尽量用接口而非具体实现类：

```java
private static Map<String, Object> beans = new HashMap<>();
```

# ？？？问题

提到的这段代码：

```java
public static Object getBean(String id) {
return hashMap.get(id);
}
```

是整个 `BeanFactory` 类中**对外提供访问 Bean 实例的核心方法**。我们来一步步分析它的含义和作用。

---

## 一、代码解析

### 方法签名：

```java
public static Object getBean(String id)
```

- `public`：表示这个方法是公开的，外部类可以调用；
- `static`：表示这是一个静态方法，可以通过类名直接调用，不需要创建对象；
- `Object`：返回值类型是 `Object`，说明它可以返回任意类型的对象（因为 Java 中所有类都继承自 `Object`）；
- `getBean`：方法名，约定为“获取一个 Bean”；
- `(String id)`：参数是一个字符串，代表要获取的 Bean 的唯一标识（即 key）；

### 方法体：

```java
return hashMap.get(id);
```

- `hashMap` 是你在类中定义的一个静态变量：

```java
private static HashMap<String, Object> hashMap = null;
```

- 它存储了所有的 Bean 实例，结构是 `<String, Object>`，也就是键值对形式；
- 这里通过传入的 `id` 去 `hashMap` 中查找对应的 Bean 实例并返回。

---

## 二、这段代码的作用是什么？

这段代码的作用是：

**根据给定的 Bean ID（key），从容器中取出对应的 Bean 实例。**

这在 Spring 等 IoC（控制反转）容器中非常常见。你可以把它理解为：

- 就像一个“仓库管理员”，你告诉它你要哪个 Bean（比如 `"userService"`）；
- 它就从内存中把已经创建好的实例返回给你；
- 不需要你自己 new 对象，而是由容器统一管理对象的生命周期。

---

## 三、举个例子说明它的使用

假设你的 `beans.properties` 文件中有如下配置：

```java
classNames=com.eagles.pojo.UserService;com.eagles.pojo.UserDAO
```

那么在静态块中，会加载这两个类，并创建实例，分别以：

- `"userService"`
- `"userDAO"`

作为 key 存入 `hashMap`。

然后你就可以这样使用：

```java
UserService userService = (UserService) BeanFactory.getBean("userService");
UserDAO userDAO = (UserDAO) BeanFactory.getBean("userDAO");
```

这就是一个简单的依赖注入（DI）过程。

## 五、优化建议（小改进）

虽然目前写法没有错误，但可以稍微加一点健壮性判断：

```java
public static Object getBean(String id) {
if (id == null || id.isEmpty()) {
    throw new IllegalArgumentException("Bean ID 不能为空");
}
Object bean = hashMap.get(id);
if (bean == null) {
    throw new RuntimeException("找不到 ID 为 [" + id + "] 的 Bean");
}
return bean;
}
```

这样可以避免空指针或找不到 Bean 的问题。

## 一、逐行解析代码

```java
package com.eagles.pojo;

import reflect.BeanFactory;
```

- 导入了你自己写的工具类 `BeanFactory`（位于 `reflect` 包下）

```java
public class Test {

        Animal animal2 = (Animal)BeanFactory.getBean("animal");

        System.out.println(animal1 == animal2);

    }
}
```

### 每一行的作用：

1. **获取第一个** `Animal` **实例：**

```java
Animal animal1 = (Animal) BeanFactory.getBean("animal");
```

- 使用 `BeanFactory.getBean("animal")` 获取一个 key 为 `"animal"` 的对象；
- 强制转换成 `Animal` 类型；
- 赋值给 `animal1`。

2. **获取第二个** `Animal` **实例：**

```java
Animal animal2 = (Animal)BeanFactory.getBean("animal");
```

- 再次通过相同的 key 获取同一个对象；
- 同样赋值给 `animal2`。

3. **比较两个引用是否指向同一个对象：**

```java
System.out.println(animal1 == animal2);
```

- 使用 `==` 判断两个引用是否指向**堆内存中的同一个对象实例**。
- 如果返回 `true`，说明 `BeanFactory` 返回的是**同一个实例**；
- 如果返回 `false`，说明每次调用 `getBean()` 都会创建一个新的实例。

## 二、关键问题：这是不是“单例”？

### 为什么做这个判断？

这段代码在测试你写的 `BeanFactory` 是否实现了**单例模式（Singleton）行为**：

- 在 Spring 等 IOC 容器中，默认的 Bean 是**单例的** —— 即容器中每个 Bean 只有一个实例；
- 这里就是在验证你的 `BeanFactory` 是否也实现了类似的行为。

---

## 三、回到你的 `BeanFactory` 类

回顾一下你写的 `BeanFactory` 中的逻辑：

```java
// 创建实例
Object instance = aClass.newInstance();

// 存入集合
hashMap.put(key, instance);
```

**结论：**

- 你在静态代码块中只执行一次 `newInstance()`；
- 所以每个 key 对应的对象都只会被创建一次；
- 之后调用 `getBean(id)` 都是从 `hashMap` 中取出已有的实例。

因此，**你的** `BeanFactory` **实现了“单例”机制！**

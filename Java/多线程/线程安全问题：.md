# 线程安全

并发：同一个对象被多个线程同时操作（万人抢票） 异步：

并行：两个或者两个以上的事情在同一时间发生（多个 任务在多个CPU上同时执行，不存在竞争关系）

# 队列和锁

现实生活中，我们会遇到”同一个资源很多人都想使用“的问题，比如，食堂排队打饭，每个人 都想吃饭。最好的解决方法就是排队，一个个来。【队列】

处理多线程问题时，多个线程访问同一个对象【并发】，并且某些线程还想修改这个对象。这个时候我们就需要线程同步。线程同步就是一种等待机制，多个需要同时访问此对象的线程进入这个对象的等待池形成队列，等待前面线程使用完毕，下个线程再使用。

## 锁带来的问题

虽然锁能解决线程安全问题，但也带来了一些副作用：

|  |  |
| --- | --- |
| **问题** | **描述** |
| **线程阻塞** | 获取不到锁的线程会被挂起，等待释放，造成性能损失 |
| **上下文切换频繁** | 锁竞争激烈时，线程频繁切换，影响效率 |
| **死锁** | A 等 B 释放锁，B 等 A 释放锁，互相僵持 |
| **优先级倒置** | 高优先级线程等待低优先级线程释放锁，效率低下 |

# 线程同步

由于同一线程的多个线程共享同一块储存空间，在带来方便的同时，也带来了访问冲突问题，为了保证数据在方法中被访问的正确性，在哦访问时加入锁机制\*synchronized\*，当一个线程获得对象的排他锁，独享资源，其他线程必须等待，释放锁可能会存在以下问题：

一个线程持有锁会导致其他所需要次锁的线程挂起。

在多线程竞争下，加锁，释放锁会导致比较多的上下文切换和调度延时，引起性能问题。

如果一个优先级高的线程等待一个优先级低的线程释放锁会导致优先级倒置，引起性能问题。

|  |  |  |
| --- | --- | --- |
| **概念** | **含义** | **示例** |
| **并发（Concurrency）** | 多个任务在**同一时间段内交替执行**，但不一定同时进行 | 单核 CPU 上运行多个线程 |
| **并行（Parallelism）** | 多个任务**在同一时刻真正同时执行** | 多核 CPU 上运行多个线程 |
| **异步（Asynchronous）** | 不按顺序执行，通常用于提高响应速度 | 网络请求后继续执行其他操作，完成后回调 |
| **资源共享** | 多个线程访问同一个对象或变量 | 抢票系统中共享库存数 |

为了解决上述问题，Java 提供了多种同步机制，确保线程之间**有序、互斥地访问共享资源**。

### 1. 使用 `synchronized` 关键字

这是 Java 中最基本的同步方式，可以加在方法上或代码块上。

### 2. 使用 `Lock` 接口（如 `ReentrantLock`）

比 `synchronized` 更灵活，支持尝试获取锁、超时、公平锁等特性。

### 3. 使用 `volatile` 关键字

适用于状态标志、变量共享等场景，保证**可见性**，但不能保证原子性。

### 4. 使用 `Atomic` 类型变量（如 `AtomicInteger`）

无锁、线程安全的变量操作，适合计数器等场景。

# synchronised

## 一、什么是 `synchronized`？

`synchronized` 是 Java 的关键字，它提供了**互斥锁机制（Mutual Exclusion）**，保证多个线程在访问共享资源时，同一时间只有一个线程可以执行被 `synchronized` 保护的代码块或方法。

### ✅ 它能解决的问题：

- **原子性**：确保一个操作是不可中断的整体；
- **可见性**：一个线程对共享变量的修改对其他线程可见；
- **有序性**：防止指令重排导致逻辑错误。

---

## 二、`synchronized` 的三种使用方式

### ✅ 1. 同步实例方法（对象锁）

```java
public class Counter {
    private int count = 0;

    public synchronized void increment() {
        count++;
    }

    public synchronized int getCount() {
        return count;
    }
}
```

- 锁的是当前对象（`this`）；
- 多个线程调用同一个对象的 `increment()` 方法时会串行化；
- 不同对象之间互不影响。

---

### ✅ 2. 同步静态方法（类锁）

```java
public class Counter {
    private static int count = 0;

    public static synchronized void increment() {
        count++;
    }

    public static synchronized int getCount() {
        return count;
    }
}
```

- 锁的是类的 Class 对象（`Counter.class`）；
- 所有该类的实例共享这个锁；
- 静态方法和实例方法不会互相阻塞。

---

### ✅ 3. 同步代码块（指定锁对象）

```java
public class Counter {
    private int count = 0;
    private final Object lock = new Object(); // 自定义锁对象

    public void increment() {
        synchronized (lock) {
            count++;
        }
    }

    public int getCount() {
        synchronized (lock) {
            return count;
        }
    }
}
```

- 更细粒度控制，只锁定关键部分；
- 可以指定任意对象作为锁（推荐使用私有对象）；
- 比同步整个方法更高效。

---

## 三、锁的类型与作用范围对比

|  |  |  |  |
| --- | --- | --- | --- |
| **使用方式** | **锁对象** | **范围** | **示例** |
| 实例方法 | 当前对象（`this`  ） | 当前对象的所有同步方法 | `public synchronized void method()` |
| 静态方法 | 类对象（`Class`  ） | 整个类的所有实例 | `public static synchronized void method()` |
| 代码块 | 指定对象（如 `lock`  ） | 指定代码块 | `synchronized(lock) { ... }` |

---

## 四、性能考虑

虽然 `synchronized` 很强大，但也有性能代价，特别是在高并发场景下：

|  |  |
| --- | --- |
| **优点** | **缺点** |
| 使用简单，语法清晰 | 粗粒度锁可能导致线程阻塞 |
| 能自动释放锁（退出同步块时） | 不支持尝试获取锁、超时等高级功能 |
| JVM 内置优化（偏向锁、轻量级锁） | 在 Java 5 之后性能已有很大提升 |

```java

public class ThreadTest13 implements Runnable {
    public static void main(String[] args) {

        //创建线程对象

        ThreadTest13 threadTest13 = new ThreadTest13();
        Thread thread1 = new Thread(threadTest13);//继承了Runable但是ThreadTest13并不是一个线程，所以得创建线程对象
        Thread thread2 = new Thread(threadTest13);

        //设置线程名称
        thread1.setName("t1");
        thread2.setName("t2");

        //开启线程
        thread1.start();
        thread2.start();

    }

    @Override
    public void run() {

        //调用方法
        doSome();
        doMore();

    }
    /*
    synchronized 修饰普通方法，那么共享对象（对象锁）一定是this即当前类的实例【ThreadTest13的实例】（threadTest13）==>对象锁，锁住的内容就是方法体
    synchronized 修饰静态方法，那么共享类【static是一个类级别的】（类锁）一定是【ThreadTest13.class】,锁住的内容就是方法体
     */
    public synchronized void doSome(){

        System.out.println("1.start-------------------------------");
        try {
            Thread.sleep(100);
        } catch (InterruptedException e) {
```

## 火车站购票案例：

```java
package com.thread;
/*
火车站购票一共有三个窗口，每个窗口用户都可以正常买票
 -假设三个窗口一共要卖100张票，但是不能卖出重复的票
 -线程同步 是需要发生等待关系(该案例容易出现线程安全的问题)
 -加锁 *synchronized*
    -同步代码块 synchronized（共享对象）{被锁住的内容}
    -synchronized 修饰普通方法
    -synchronized 修饰静态方法
 */
public class ThreadTest12 {

    public static void main(String[] args) {

        //创建一个Ticket对象
        Ticket ticket = new Ticket(100);//共享对象
        //创建窗口对象
        Window window01 = new Window(ticket);
        Window window02 = new Window(ticket);
        Window window03 = new Window(ticket);

        //设置线程名称
        window01.setName("window01");
        window02.setName("window02");
        window03.setName("window03");

        //开启线程
        window01.start();
        window02.start();
        window03.start();
    }

}
//窗口类似于线程
class  Window extends Thread{

    //聚合一个Ticket类
    private  Ticket ticket;
    private static Object object =new Object();

    public Window(Ticket ticket) {
        this.ticket = ticket;

    }

    @Override
    public void run() {
        //写入一个死循环
        while (true){
            
            synchronized (this.ticket){//this是当前类的实例，即Window类

                try {
                    Thread.sleep(100);
                } catch (InterruptedException e) {
                    throw new RuntimeException(e);
                }

                if (ticket.getCount() <= 0){
                    break;
                }

                System.out.println(Thread.currentThread().getName()+"卖出去了一张票，编号为："+ticket.getCount());
                //票数减一
                ticket.setCount(ticket.getCount()-1);
            }

        }
    }
}

class Ticket{
    private  Integer count;

    public Ticket(Integer count) {
        this.count = count;
    }

    public Integer getCount() {
        return count;
    }

    public void setCount(Integer count) {
        this.count = count;
    }

    @Override
    public String toString() {
        return "Ticket{" +
        "count=" + count +
        '}';
    }
}
```

/\*线程安全原理：

1.当三个线程t1、t2、t3来到这行代码时会争夺对象锁（对象锁只有一把）

2.假设t1抢到了ticket的对象锁，t1进入synochronized代码块里面去执行任务，其他的线程必须要等待

3.那么t2、t3两个线程只能在锁池中进行等待，直到t1执行完所有的任务，这个时候t1会释放对象锁

4.这个时候t2het3才再有机会去争夺对象锁

如果下面代码块这样写 synchronized ("hello"){} 程序依然可以使得线程同步

这是因为"hello"这个字符串他的空间是开辟在方法区里面的，方法区本身也是一个共享对象（字符串被所有线程所共享）

只要是一份内存地址放在这里就可以，空间唯一就可以（例如static）private static Object object =new Object();

当然如果这里没有static private Object object =new Object();

//创建窗口对象

Window window01 = new Window(new Object（）);

Window window02 = new Window(new Object（）);

Window window03 = new Window(new Object（）);

将会使得线程并发，没有等待关系，因为每次new 都会指向不同的一份空间，空间不唯一

这时虽然synchronized (object){}也可以使得线程同步，但是他会约束所有线程，因为他是object

但是如果放入的是synchronized (this.ticket){}它就只会约束Window这个类创造出来的三个线程（ticket是最精确的约束对象）

当别的线程进入ticket这个线程对象的时候不用进行排队

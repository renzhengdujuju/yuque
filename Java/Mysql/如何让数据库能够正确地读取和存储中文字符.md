### 1. 创建数据库时指定字符集

在创建新的数据库时，可以通过指定 `CHARACTER SET` 和 `COLLATE` 来确保支持中文（即使用 `utf8mb4` 或 `utf8` 字符集）：

```sql
CREATE DATABASE your_database_name 
CHARACTER SET utf8mb4 
COLLATE utf8mb4_unicode_ci;
```

这里使用 `utf8mb4` 而不是 `utf8` 是因为 `utf8mb4` 支持更广泛的字符集，包括 Emoji 表情等。

### 2. 创建表时指定字符集

在创建表的时候，同样需要指定字符集。例如：

```sql
CREATE TABLE student (
  Id INT(10) PRIMARY KEY AUTO_INCREMENT,
  Name VARCHAR(20) NOT NULL,
  Sex VARCHAR(4),
  Birth YEAR,
  Department VARCHAR(20) NOT NULL,
  Address VARCHAR(50)
) CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

这样做可以确保表中的所有字段都能正确处理中文字符。当然，你也可以针对特定的字段单独设置字符集：

```sql
Name VARCHAR(20) CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci NOT NULL,
```

### 3. 确保连接字符集正确

当你通过应用程序或命令行工具连接到 MySQL 数据库时，还需要确保连接使用的字符集也是 `utf8mb4`。可以在连接之后执行以下 SQL 命令来设置：

```sql
SET NAMES utf8mb4;
```

或者，在建立连接时直接通过参数指定字符集。例如，在使用命令行连接时：

```sql
mysql -h hostname -u username -p --default-character-set=utf8mb4
```

对于编程语言中的数据库连接配置，也需要相应地设置字符集。以 PHP 的 PDO 扩展为例：

```sql
$dsn = 'mysql:host=hostname;dbname=your_database;charset=utf8mb4';
```

### 4. 检查现有数据库/表的字符集

如果已经存在数据库或表，你可以检查它们当前的字符集设置，并在必要时进行修改。

- 查看数据库字符集：

```sql
SELECT DEFAULT_CHARACTER_SET_NAME, DEFAULT_COLLATION_NAME 
FROM INFORMATION_SCHEMA.SCHEMATA 
WHERE SCHEMA_NAME = 'your_database_name';
```

- 查看表字符集：

```sql
SHOW TABLE STATUS WHERE Name = 'your_table_name';
```

- 修改数据库字符集：

```sql
ALTER DATABASE your_database_name CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

- 修改表字符集：

```sql
ALTER TABLE your_table_name CONVERT TO CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

这是一个在 MySQL 中非常重要的设置，用于**指定字符集（Character Set）**。下面我们来详细解释它的含义、作用以及为什么推荐使用它。

## 解释CHARACTER SET utf8mb4 ：

## 一、基本含义

```sql
CHARACTER SET utf8mb4
```

表示：**该对象（数据库、表或字段）使用的字符集是** `utf8mb4`

### 拆解关键词：

###### 1.`CHARACTER SET`:

表示“字符集”，决定了可以存储哪些字符（如中文、英文、表情符号等）

###### 2.`utf8mb4`:

是一种字符集名称，支持完整的 Unicode 字符，包括所有语言文字和 Emoji 表情

|  |  |
| --- | --- |
| **关键词** | **含义** |
| `CHARACTER SET` | 表示“字符集”，决定了可以存储哪些字符（如中文、英文、表情符号等） |
| `utf8mb4` | 是一种字符集名称，支持完整的 Unicode 字符，包括所有语言文字和 Emoji 表情 |

## 解释COLLATE utf8mb4\_unicode\_ci：

`COLLATE utf8mb4_unicode_ci;` 是 MySQL 中用于指定文本数据如何进行比较和排序的子句。让我们拆解一下这个术语，以便更好地理解它的含义：

### 1. **字符集 (Character Set)**

- `utf8mb4`：这是一个字符编码标准，是 `utf8` 的超集，支持更广泛的字符集，包括所有 Unicode 字符（如各种语言的字符、表情符号等）。相比于 `utf8`，`utf8mb4` 可以存储 4 字节长度的字符，而 `utf8` 只能存储最多 3 字节长度的字符。

### 2. **排序规则 (Collation)**

- `unicode_ci`：这是在特定字符集下使用的排序规则（Collation）。它决定了字符串之间如何进行比较、排序以及搜索。

- `unicode`：表示使用 Unicode 标准来进行字符的比较和排序。
- `ci`：代表“case-insensitive”，意味着大小写不敏感。也就是说，在比较或排序时，“A”和“a”被视为相同的字符。

### 3. **综合解释**

因此，`COLLATE utf8mb4_unicode_ci;` 表示：

- 使用 `utf8mb4` 字符集来存储和处理数据。
- 在比较和排序字符串时，遵循 Unicode 标准，并且忽略大小写的差异。

例如，如果你有两个字符串 "Hello" 和 "hello"，在使用 `utf8mb4_unicode_ci` 排序规则的情况下，它们会被认为是相等的。

### 4. **其他常见的 Collation**

- `utf8mb4_general_ci`：也是一个常用的 collation 规则，同样是大小写不敏感，但它的比较速度更快一些，因为它的比较算法比 `unicode_ci` 简单。
- `utf8mb4_bin`：基于字符的二进制表示进行比较，区分大小写，并且严格根据字节值进行比较。

选择哪种 `collation` 主要取决于你的应用需求。如果需要精确匹配（如用户名），你可能希望使用 `utf8mb4_bin`。对于大多数情况，尤其是涉及多语言支持的应用中，`utf8mb4_unicode_ci` 或 `utf8mb4_general_ci` 更为常用。

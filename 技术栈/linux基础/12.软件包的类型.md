# yum/dnf

yum/dnf是红帽系列的发行版本上用来下载和安装软件包的一个工具

我们可以使用`yum install xxx`命令来安装一个软件

但是大家有没有考虑过一个问题？yum工具是去哪里找到这些软件包的呢？

这就不得不提到`yum源`,所谓`源`的意思就是指这些软件包的来源，也可以成称之为`软件仓库`

## dnf与yum的对比

**YUM (Yellowdog Updater, Modified)**：

- 是 RHEL 8 及之前版本使用的包管理工具。
- 提供了一个简单的命令行接口，用来安装、更新、删除和管理 RPM 软件包。
- 基于 Python 2 开发，在性能和依赖性解析方面存在一定的限制。

**DNF (Dandified YUM)**：

- 是 YUM 的下一代替代工具，首次在 Fedora 18 引入，并从 RHEL 8 开始逐步取代 YUM，到了 RHEL 9 完全淘汰 YUM。
- 采用了更先进的依赖解析器和更高效的代码。
- 基于 Python 3 开发，支持现代特性和技术，性能更高。

**RockyLinux中yum命令的本质：**

```plain
[root@localhost bin]# ll /usr/bin/ | grep dnf
lrwxrwxrwx. 1 root root          5 Apr 14  2024 dnf -> dnf-3
-rwxr-xr-x. 1 root root       2094 Apr 14  2024 dnf-3
lrwxrwxrwx. 1 root root          5 Apr 14  2024 yum -> dnf-3
```

由此可以看出，yum命令和dnf命令都链接自dnf-3。实际上dnf-3才是包管理器的真正可执行程序，代表基于python3开发。这样链接是为了我们使用起来更方便。

1. sed命令功能：

• sed是一个流编辑器，用于对文本进行过滤和转换。

• 在这里，sed被用来修改/etc/yum.repos.d/rocky-extras.repo和/etc/yum.repos.d/rocky.repo这两个文件。

2. 命令细节：

• -e选项表示后面跟着的是一个sed编辑命令。

• 第一个编辑命令是将文件中以mirrorlist=开头的行替换为#mirrorlist=，即在行首添加注释符号#，使其失效。

• 第二个编辑命令是将以`#baseurl=<http://d1.rockylinux.org/$contentdir`>开头的行替换为`baseurl=<https://mirrors.ustc.edu.cn/roc`>

• -i.bak选项表示对文件进行原地编辑，并生成一个以.bak为后缀的备份文件。

3. 修改的文件：

• /etc/yum.repos.d/rocky-extras.repo和/etc/yum.repos.d/rocky.repo是Yum仓库的配置文件，用于定义软件包的来源。

4. 目的：

• 通过修改这些配置文件，用户可能希望更改Yum仓库的镜像源，从默认的Rocky Linux镜像源切换到中国科学技术大学（USTC）的镜像源，以提高下载速度或解决访问问题。

#### 软件包组解释
##### Environment Groups（环境组）
- **Server with GUI** GNOME 桌面环境及相关应用
- **Server** 无图形界面的纯服务器环境，包含基本的服务器组件（SSH、存储管理、网络管理工具等）
- **Workstation** 桌面工作站环境，适合普通用户和开发人员，包含办公软件、多媒体支持和开发工具
- **KDE Plasma Workspaces** KDE Plasma 桌面环境及其相关工具
- **Custom Operating System** 自定义操作系统环境，用户可以手动选择需要的软件包
- **Virtualization Host** 专用于虚拟化的环境，包含 KVM、`libvirt` 和虚拟化管理工具
- **Minimal Install** 最小化安装，仅包含基础系统和命令行工具

---

##### Available Groups（可用的软件包组）
- **Fedora Packager** 用于构建 Fedora 或 RHEL/CentOS 软件包的工具（如 `rpmdevtools` 和 `mock`）
- **VideoLAN Client** VLC 媒体播放器及其依赖项
- **Xfce** 轻量级桌面环境，适合资源受限的设备或低性能机器
- **Legacy UNIX Compatibility** 提供传统 UNIX 系统兼容的工具和库（如 `csh` 和 `compat-libstdc++`）
- **Console Internet Tools** 基于命令行的互联网工具（如 `wget`、`curl` 和文本浏览器 `lynx`）
- **Container Management** 用于管理容器的工具（如 Podman 或 Docker）
- **Development Tools** 常用开发工具（如 `gcc` 编译器、`gdb` 调试器和 `git` 版本控制工具）
- **.NET Development** 用于开发和运行 .NET 应用程序的工具和运行时
- **Graphical Administration Tools** 图形化的系统管理工具（如磁盘管理和网络配置工具）
- **Headless Management** 用于远程管理无图形界面服务器的工具
- **Network Servers** 常见网络服务（如 `httpd`、`vsftpd` 和 `bind`）
- **RPM Development Tools** 用于构建和维护 RPM 软件包的工具（如 `rpmbuild` 和 `createrepo`）
- **Scientific Support** 科学计算工具和库（如 `numpy` 和 `scipy`）
- **Security Tools** 安全扫描、入侵检测和分析工具（如 `nmap`、`wireshark` 和 `clamav`）
- **Smart Card Support** 与智能卡相关的工具和库，支持基于智能卡的身份认证
- **System Tools** 常用的系统管理工具（如磁盘管理和日志分析工具）

**挂载ISO：把光盘变成文件夹**

mount Rocky-9.4-x86\_64-dvd.iso /media/cdrom/

- **原理**：你把 `Rocky-9.4...iso` 这个文件，通过 loop 设备挂载到了 `/media/cdrom` 目录。
- **现象**：`df -h` 显示 `/dev/loop0` 被占用了，说明系统把这个 ISO 文件当成了一块物理硬盘来读取。
- **结果**：现在，ISO 里的所有软件包（RPM 文件）都可以通过访问 `/media/cdrom` 目录拿到了。

**清理旧仓库：断舍离**

如果不删除原有的官方源配置，当你运行 `yum install` 时，系统可能会尝试去连接互联网上的官方服务器。在内网环境下，这会导致超时报错。

**配置 local.repo：绘制藏宝图**

- **baseurl=file://...**：这里的 `file://` 协议告诉 yum 是本地读取，速度极快（取决于硬盘读写速度）。
- **gpgcheck=0**：关闭签名检查。在生产环境中，为了安全通常设为 `1` 并导入密钥，但在做实验或内网测试时，设为 `0` 可以避免很多麻烦的报错。

**验证安装：见证奇迹时刻**

- **过程**：当你敲下回车，yum 会去读取刚才配置的 `local.repo`，发现 `httpd` 这个包就在 `/media/cdrom/AppStream/Packages` 目录下，于是直接复制过来安装。
- **意义**：这证明你的本地源配置**完全成功**。你现在可以在没有网络的情况下，安装光盘中包含的任何软件（比如 `vim`, `gcc`, `nginx` 等）。

**永久生效：**

# 在 /etc/fstab 末尾添加一行

/root/Rocky-9.4-x86\_64-dvd.iso /media/cdrom iso9660 defaults,loop 0 0

### `/dev/loop0`**是什么时候产生的？**

它是在你执行 `mount` 命令的那一瞬间，“无中生有”被系统征用的。

让我们回到你刚才的操作步骤，看看后台到底发生了什么：

1. **平时（休眠状态）**：  
   Linux 内核启动时，就已经预先在内存里准备好了几个“空壳子”设备，名字分别叫 `/dev/loop0`, `/dev/loop1` ... `/dev/loop7`。

- 这时候它们**没有任何内容**，就像没有插卡槽的读卡器，虽然存在，但没用。

2. **关键时刻（产生瞬间）**：  
   当你敲下回车键执行这条命令时：

mount Rocky-9.4-x86\_64-dvd.iso /media/cdrom/

系统内部其实自动帮你做了一件你没看见的事：

- 系统发现你要挂载的是一个**文件**（ISO），而不是物理光盘。
- 系统心想：“`mount` 命令只认识硬件（块设备），不认识文件啊，怎么办？”
- 于是，系统转头去找那个闲置的 `/dev/loop0`。
- 系统下达指令：“嘿，`/dev/loop0`，你现在**绑定**这个 `Rocky-9.4...iso` 文件，假装自己是一张物理光盘！”
- **就在这一毫秒，**`/dev/loop0`**产生了实质意义。** 它不再是空壳，它现在代表了那个 ISO 文件。

3. **挂载后**：  
   系统再执行挂载操作，把已经变身成“虚拟光盘”的 `/dev/loop0` 挂到 `/media/cdrom` 目录上。

**结论：** 它是**在你挂载 ISO 文件的那一刻**，由系统自动分配并激活的。

### `/dev/loop0` **到底表示什么意思？**

我们可以把它理解为**“欺骗内核的中间人”**。

#### 为什么需要这个“中间人”？
Linux 有一个死规定：`mount`**（挂载）命令只能挂载“块设备”，不能直接挂载“普通文件”。**

- **块设备**：比如硬盘 (`/dev/sda`)、U盘、光驱。它们的特点是可以按“块”来读写数据，想读第1页就读第1页，想读第100页就读第100页。
- **普通文件**：比如你的 `Rocky-9.4...iso`。在系统眼里，它只是一长串连续的数据流。

如果你直接告诉系统：“请把 `xxx.iso` 这个文件挂载到目录上”，系统会报错，因为它觉得你在胡扯——**文件怎么能当硬盘用呢？**

#### Loop 设备的作用
这时候 `/dev/loop0` 就登场了。它的作用是**把一个普通文件，包装成一个块设备**。

- **对下（面对文件）**：它读取 ISO 文件里的数据。
- **对上（面对系统）**：它举手报告：“我是 `/dev/loop0`，我是一张标准的磁盘，请像读写硬盘一样读写我吧。”

**打个比方：**

- **ISO 文件** = 一本写满字的**小说书**（普通文件）。
- **Mount 命令** = 一个只听得懂**电脑指令**的机器人。
- **问题**：你想让机器人读这本书，但机器人说：“我只接收 U 盘或光盘，不读书。”
- **Loop0 设备** = 一个**翻译官**。他把书里的内容扫描进去，然后模拟成一个 U 盘插在机器人身上。
- **结果**：机器人以为自己插了个 U 盘（`/dev/loop0`），开始读取数据，实际上数据源头是那本书（ISO 文件）。

`file:///`

**前两个斜杠** `//` **是属于协议格式的“固定搭配”，而第三个斜杠** `/` **才是代表你电脑根目录的“路径起点”。**

URL 的通用标准格式是这样的：`协议://主机名/路径`

**这两个斜杠只是“占位符”，表示协议头结束了。**

### 实验二：提供内网服务器软件包更新

一台server1服务器可以访问公网，一台server2服务器无法访问公网

我们可以在这台能够访问公网的服务器上下载好软件包，通过http或者ftp提供给内网中的server2机器安装软件包

**server1：**

第一步：下载软件包，可以使用`--downloadonly`选项仅下载不安装

第二步：将软件包放到合适的位置上，并且创建软件索引数据

```bash
[root@localhost ~]# yum clean all                  # 清理缓存
[root@localhost ~]# yum update -y --downloadonly --downloaddir=/packages   # 仅下载更新包
[root@localhost ~]# ls /packages/    # 查看下载的包

[root@localhost ~]# mkdir /var/ftp/update
[root@localhost ~]# find /packages -iname "*.rpm" -exec cp -rf {} /var/ftp/update/ \;   或者rsync -av /packages/ /var/ftp/update/
[root@localhost ~]# yum -y install createrepo      # createrepo用来创建软件包的索引
[root@localhost ~]# createrepo /var/ftp/update/    # 创建软件包的索引
```

第三步：部署ftp文件服务器，将软件包通过ftp协议共享给sever2

```bash
# 部署ftp服务并且启动
[root@localhost ~]# yum -y install vsftpd
[root@localhost ~]# vim /etc/vsftpd/vsftpd.conf        # 更改ftp的配置文件，允许匿名登录
anonymous_enable=yes
“anonymous”（匿名），这意味着允许匿名用户访问FTP服务。

[root@localhost ~]# systemctl start vsftpd
管理员成功启动FTP服务，使得FTP服务器开始并接受连接。
# 关闭防火墙和selinux
[root@localhost ~]# systemctl stop firewalld
[root@localhost ~]# setenforce 0
```

**server2：**

在server2上我们编写repo文件，软件的来源是有server1通过ftp服务提供

```bash
[root@localhost ~]# rm -rf /etc/yum.repos.d/*.repo    #干掉所有的仓库
[root@localhost ~]# vi /etc/yum.repos.d/update.repo
只要最后文件的后缀是.repo就可以识别到
[update]
name=RockyLinux update
baseurl=ftp://192.168.75.10/update
ftp这个命令是从/var/ftp目录开始的，所以后面跟server1的IP
gpgcheck=0
enabled=1                                    

# 关闭防火墙和selinux
[root@localhost ~]# systemctl stop firewalld
[root@localhost ~]# setenforce 0

[root@localhost ~]# yum clean all    
[root@localhost ~]# yum update -y        # 更新测试
```

解释：

```bash
ftp://   使用ftp协议访问

为什么的/update不是/var/ftp/update？
因为vsftpd默认把/var/ftp作为匿名用户的根目录，匿名登录后。FTP看到的/实际上就是服务器上的/var/ftp
所以：
服务器上的路径：/var/ftp/update
FTP 访问路径：   ftp://192.168.75.10/update
就像浏览器访问 Nginx 时，/var/www/html/index.html 对应 http://x.x.x.x/index.html，道理一样。

整个流程：
server2 执行 yum update
        ↓
读取 /etc/yum.repos.d/update.repo
        ↓
baseurl 指向 ftp://192.168.75.10/update
        ↓
通过 FTP 连接到 server1，下载 repodata/ 索引
        ↓
根据索引找到需要的 .rpm 包，从 FTP 下载并安装
```

# RPM

在RHEL系列的系统上所使用的软件包为rpm包，上面使用的yum为在线安装软件包。除了在线的安装方法，我们还可以将rpm包下载到本地，然后使用rpm工具来安装这个软件包

- rpm工具使用分为安装、查询、验证、更新、删除等操作
- rpm包的格式说明：

```bash
[root@atopos ~]# rpm -ivh httpd-2.4.6-93.el7.centos.x86_64.rpm
- httpd：包名
- 2：主版本号
- 4：次版本号
- 6：修订次数，指的是第几次修改bug
- 93：release（第几次发布，指的是简单的修改参数）
- e17：操作系统版本
- x86_64：64位操作系统
```

- 命令格式

```bash
[root@atopos ~]# rpm [选项] 软件包
```

## 选项

**安装：**

- -i：install的意思，安装软件包
- -v：显示附加信息，提供更多详细信息
- -V：校验，对已安装的软件进行校验

**查询：**

- -q：查询，一般跟下面的参数配合使用
- -a：查询所有已安装的软件包
- -f：系统文件名（查询系统文件属于哪个安装包）
- -i：显示已安装的rpm软件包信息
- -l：查询软件包文件的安装位置
- -p：查询未安装软件包的相关信息
- -R：查询软件包的依赖性

**卸载：**

- -e：erase
- --nodeps：忽略依赖

**升级：**

- -U：一般配合vh使用

## 实例：安装

```bash
[root@localhost ~]# rpm -ivh https://rpmfind.net/linux/almalinux/9.4/AppStream/x86_64/os/Packages/httpd-2.4.57-11.el9_4.x86_64.rpm

# 或者
```

## 编译

源码包编译三部曲

```bash
- 第一步：
./configure 
#可以指定安装路径，启用或者禁用功能等，最终生成makefile

- 第二步
make 
#按Makefile文件编译。可以加 -j 2 参数使用两个cpu核心进行编译

- 第三步
make install
#按Makefile定义的文件路径安装

make clean
#清除上一次make命令所产生的object文件，要重新执行
configure时，需要执行make clean。
```

### 补充：压缩与解压缩

**打包一个文件或者目录**：

```bash
tar -cvf archive.tar /path/to/directory

-c 表示创建一个新的归档文件。
-v 表示在压缩过程中显示详细信息（verbose 详细模式）。
-f 指定归档文件的名称。

# 如果要创建gzip压缩包
tar -zcvf archive.tar.gz /path/to/directory
```

**解压缩：**

```bash
tar -xvf archive.tar

-x 表示解压缩。
-v 表示显示详细信息。
-f 指定要解压缩的归档文件。

# 如果归档文件是使用 gzip 压缩的，比如 archive.tar.gz，则需要添加 -z 选项：

tar -zxvf archive.tar.gz
```
